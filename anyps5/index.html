  • #6060 perf(agc): keep Windows host imports of write-watched private memory watched15 Oct 2026

    Fixed a Windows regression on main that had made games compare whole memory snapshots byte by byte, up to 1.9 TB every 10 seconds. Sword of the Sea went from about 2 to 7.7–9.5 FPS, and other contributors confirmed big gains on NVIDIA and AMD across 9 games, including Astro Bot 0.42 → 2.89 FPS and 3.0 → 15.1 FPS.

    Details

    An earlier change (#5596) made the game's main memory on Windows into private write-watched memory (GetWriteWatch, the Windows feature that reports which pages the CPU has written). After that, every host import, where Vulkan reads the game's memory in place instead of through a copy, fell back to comparing whole memory snapshots byte by byte, and Sword of the Sea dropped from 8.13 to 2.09 FPS. The fix adds a startup probe that checks whether the driver keeps write-watch working on imported memory, then settles each new import with a 4-byte GPU read on a second queue, so the driver's one-time page marks are cleared and the import stays watched without any comparisons. A fallback through another queue family covers AMD drivers that expose only one graphics queue. On my two boxes Sword of the Sea went from 3.0 to 9.5 FPS (RTX 3060) and from about 2.0 to 7.7 FPS (RTX 4060). Snapshot compares went from 1.5–6.2 million calls (0.5–1.9 TB) per 10 s down to 1, and the crash that the competing approach (#5851) hit in 2–3 of 10 boots never happened (0 of 10). Other contributors confirmed it on NVIDIA and AMD: Astro Bot 0.42 → 2.89 FPS (RX 9070 XT), 3.0 → 15.1 FPS (RTX 4090) and 1.4 → 3.5 FPS (RTX 3080 Ti); SuperTuxKart 4.5 → 7.5 FPS (RTX 3070 Laptop) and 5.1 → 7.2 FPS (Radeon 860M); ccleste about 75 → 113 FPS; Besiege 14 → 21 FPS (+50%); Ghost of Yōtei's first lit frame 80 s → 40 s; Minecraft Dungeons II from not reaching gameplay within 200 s to loading normally; and a RetroArch Flycast core from 75–78% to 89–90% of real-time speed. #5851 was closed in favour of this PR.

  • #6168 fix(agc): recycle detiler descriptor pools once their batches complete15 Oct 2026

    Fixed a GPU memory leak that grew to 31.6 GB and crashed long sessions after 12–22 minutes. A 40-minute run now finishes with memory flat at about 10 GB.

    Details

    The texture detiler, a GPU shader that converts the PS5's tiled texture layouts into normal linear ones, reset its Vulkan descriptor pools only when the command recorder went idle. A game running fast enough never goes idle, so a new pool was added every 64 detiles until Vulkan ran out of device memory. With #6060, Sword of the Sea climbed to about 31.6 GB and crashed after 12 and 22 minutes. Each pool now records the newest GPU batch that used it and is reset and reused once that batch has completed. A 40-minute run then finished with no crash (23,678 frames), and memory stayed flat at 10.0–10.4 GB. I reproduced the same crash with the alternative #5851, which showed the bug was already on main and only appeared once games ran faster. Others confirmed the new test fails on the old code (lavapipe on Linux, Radeon 680M) and passes on an RTX 5080, a Radeon iGPU and an RTX 4090.

  • #5281 feat(agc): copy HLE for the 16-byte stream copy kernel14 Oct 2026

    Replaced the most expensive GPU program on Sword of the Sea's title screen, a 16-instruction copy kernel costing about 11 ms a frame, with a direct buffer copy. Title FPS rose 3.8–4.5%.

    Details

    The game runs a small 16-instruction compute kernel every frame just to copy 3 MiB of buffer data, and recompiling and running it as a shader cost about 11 ms of GPU time per frame on an RTX 4060. This adds an HLE (high-level emulation) path: the driver recognises that exact kernel word for word, checks that the buffer descriptors make it a bit-exact copy, and does a native GPU buffer copy instead. Anything it can't prove safe (bad alignment, short source, over 16 MiB, overlapping ranges) falls back to the shader. Title FPS went from 4.90 to 5.08 on an RTX 3060 and from 3.80 to 3.97 on an RTX 4060, GPU time per frame dropped from 94 to 86 ms and from 122 to 111 ms, and 1,431 kernel launches were replaced in a run with identical rendered frames. At the maintainer's request I added a test that refuses every single-bit change to the kernel and checks every destination word across nine dispatches.

  • #7427 perf(agc): hand pending results over to an image whose DCC keys are a clear code20 Oct 2026

    In review. Skips dead GPU write-backs that made up 90% of the pending bytes on Minecraft Dungeons II's title screen: about 60 GB → 14.7 GB per 10 seconds, +9.2–9.6% FPS.

    Details

    Before refreshing a storage image, the driver wrote back every other image's pending GPU results in that memory. When the new image's compression metadata says it's just a fast clear (Unreal does this constantly with temporary textures), those write-backs are wasted work. The change hands those results over without writing them back, under strict conditions and exact rules for later reads, overwrites and CPU stores, with a test covering four orderings. Title FPS rose 9.6% on an RTX 4060 (3,072 MiB cache), 9.2% on an RTX 3060 and 3.0% on Sword of the Sea. It doesn't help gameplay scenes, where the hand-over never fires.

  • #6490 perf(agc): retile storage write-back windows straight into their unit-shadow slabs19 Oct 2026

    In review. Writes GPU results straight into their final memory instead of copying them twice, halving write-back GPU time and adding 4.8–5.5% FPS; confirmed by AlxcBTW on an RTX 5070 Laptop.

    Details

    A storage write-back copies GPU-written image results back into the game's memory layout. Each window was retiled into a scratch buffer and then copied into the unit-shadow slabs, so every byte was written twice, about 53.7 GB of extra copies per 10 s on Minecraft Dungeons II. Windows that meet strict alignment and coverage rules are now retiled straight into their slabs, and everything else keeps the old path. Write-back GPU time dropped about 45% (17.4 → 9.5 ms per frame on an RTX 3060, 14.8 → 8.3 ms on an RTX 4060), and title FPS rose 5.5% on Sword of the Sea and 4.8% on Minecraft Dungeons II. AlxcBTW confirmed it on an RTX 5070 Laptop: write-back time halved and the title gained about 4%.

  • #7560 perf(shader): drop window stores no relative read can see20 Oct 2026

    In review. Shader recompiler pass that deletes 2,117 of 2,196 useless stores in Minecraft Dungeons II's hottest GPU program, shrinking it 11% and cutting the three hottest programs by 6–15%.

    Details

    AMD GPUs support relative register addressing, which the shader recompiler emulates with a per-thread memory window, storing every register write in case a relative read needs it. Most of those stores could never be read, and they also blocked other optimisation passes. A new backward-liveness pass deletes the stores no later relative read can see, so the existing passes can clean up behind them. On an RTX 3060 the title went from 8.10 to 8.28 FPS, and the three hottest programs dropped from 7.9 to 7.0, 6.2 to 5.3 and 2.55 to 2.41 ms per frame. Frame captures matched main, and another contributor found no regressions on an Apple M2 Max.

  • #7461 perf(agc): wait only for the key bytes' writers when reading DCC keys under a unit shadow19 Oct 2026

    In review. Removes 59–80 unnecessary full GPU waits every 10 seconds (111–193 ms of stalls) on Minecraft Dungeons II's title screen.

    Details

    DCC is AMD's colour compression, and its keys are small per-block metadata. When the driver read DCC keys under a unit shadow (the GPU-side copy of guest memory), it waited for every GPU batch in flight while holding the GPU lock. Now it waits only when a pending write actually overlaps the key bytes, and only up to that write. None of the old waits were needed (the keys read the same before and after). The title went from 8.11 to 8.22 FPS on a GPU-bound card, with no change on Sword of the Sea, and a new test fails with the old full wait.

  • #6499 perf(agc): keep a host import across a split of its guest range19 Oct 2026

    In review. Keeps a GPU memory import alive when a game unmaps part of its range, cutting each re-import from about 500 ms to under 0.02 ms in a synthetic test; real-game gains not shown yet.

    Details

    When a game protects or unmaps part of a large memory range, the guest memory manager rebuilt every piece of it, so the GPU import of the untouched remainder was thrown away and recreated, which costs hundreds of milliseconds with #6060's watched imports. This keeps an import whose head or tail was cut off and re-attaches it to the surviving range, using a backing serial to prove those pages were untouched. In a synthetic test of the pattern reported on Astro Bot, each re-import dropped from 472–560 ms to under 0.02 ms. Two testers saw no in-game gain on Astro Bot, and one found the game places guard pages in the middle of the range, which this version doesn't handle yet.

  • #5046 feat(agc): trace slices and GPU ranges carry the recorder batch they belong to14 Oct 2026

    Linked every GPU batch in a performance trace to the CPU work that recorded it, which showed Sword of the Sea's 16 ms GPU batches came from only ~1.6 ms of CPU work.

    Details

    Performance traces showed the GPU's command batches and the CPU's work separately, with nothing to say which CPU work recorded which GPU batch. Now each recorder batch gets an ID while a trace runs, the thread that opened it stamps the ID on every CPU slice it records, and the batch's GPU time ranges carry the same ID into the trace. On the Sword of the Sea main menu, 10,399 of 10,406 GPU slices and 299,401 of 301,361 CPU slices carried an ID. Joining on it showed the scene was GPU-bound, which pointed the performance work at the GPU side.

  • #2295 test(net): reset the closed peer with unread data so the send fails at once9 Oct 2026

    Fixed a network test that failed on every run on Windows machines with a VPN or network filter installed. It now passes everywhere, and the full suite passed 507/507.

    Details

    The test checks that a send fails once the peer has closed its socket, and allowed only 100 tries 1 ms apart. With a network filter driver installed (Cloudflare WARP, ProtonVPN), sends kept succeeding for about 19 s, so the test always failed. A plain Winsock program with no AnyPS5 code behaved the same, which showed the cause was the host, not the PS5 networking library. The test now leaves unread data in the socket before closing it, which makes TCP send a reset at once, so the next send fails on the first try whatever is installed. The check itself is unchanged.

  • #6905 perf(agc): store whole words of 1- and 2-byte texels in the detile shader16 Oct 2026

    In review. Makes detiling of 1- and 2-byte texture formats 2.2–6× faster by writing each 4-byte word once instead of with atomics per texel.

    Details

    The detile shader moves one texel per GPU thread, so for small formats (R8, R16 and similar) 2–4 threads shared each 4-byte word and wrote it with atomic operations, running at 9–44 GB/s against 253 GB/s for 4-byte texels. New variants combine each word's texels in workgroup shared memory and write the word once, with the old path at edges so the output bytes are identical. On an RTX 4060, 1-byte buffer detiles got 6.0× faster (228.9 → 37.9 µs), 2-byte ones 2.6×, and 1-byte image retiles 2.2×. No current game is bound by these paths, so it claims no FPS gain. Other contributors confirmed the byte-exact test on an AMD Radeon 780M and an Apple M2 Max.
